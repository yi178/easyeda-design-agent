# Contributing

Contributions should preserve the platform safety model.

## Good First Areas

- Snapshot schema examples.
- Design graph fixtures.
- Validators for common beginner hardware mistakes.
- Markdown report improvements.
- EasyEDA API compatibility notes.

## Skill Requirements

Every production skill should include:

- `SKILL.md`
- input schema
- output schema
- fixtures
- evals
- clear safety assumptions

## Pull Request Checklist

- Tests or evals cover the behavior.
- New write operations use `DesignPlan`.
- No arbitrary EasyEDA JavaScript execution was added.
- Documentation explains user-visible behavior and safety limits.
